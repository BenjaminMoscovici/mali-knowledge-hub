# MKH continuous measured improvement

Keep the accepted live baseline protected. A rejected candidate is diagnostic
evidence, not the end of a sprint. Continue:

Diagnose → modify → test → compare → keep/reject individual changes → combine
improvements → retest → deploy when the combined candidate is materially better
and every protected gate and release prerequisite is established.

Retain measured follow-up interpretation, clarification, conversation latency,
token, call and cost improvements. Remove or redesign individual regressions;
do not discard successful changes merely because their combination failed.
Use the same frozen, rolling, held-out and conversational suites. Preserve raw
attempts and their hashes; failed requests are never silently resampled. If
repeated attempts exhaust an approach, document why and switch approach.

Normal development decisions do not require Publisher approval. Actual access
or transmission approval restrictions must still be respected; continue all
unaffected implementation and offline verification while a dependent check is
blocked. Unknown protected metrics do not become passes.

Radar v2 reports professional quality multiplied by demonstrated capability
coverage. Missing operational layers reduce capability. Keep the original v1
artifacts reproducible, and never average away hard gates. New source integration
remains paused until the current benchmark and improvement sprint are complete.
